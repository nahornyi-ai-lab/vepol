# v1.2.0 — Plan your day, in your language, from the first morning

Vepol 1.2.0 adds a morning planning dialog to Vepol Desktop, rewrites the
morning brief to be read in a minute, and makes everything Vepol writes for
you follow your language. A fresh install now runs its daily routine without
hand fixes, and a new install grants Claude Code only what Vepol needs. The
stable core keeps its contracts. Some other `kb-*` commands change an exit
code, an output or a default; every one is listed under
[If you already use Vepol](#if-you-already-use-vepol).

## What you get

- **Plan my day, in Vepol Desktop.** The Memory view opens with a Today card:
  the day's goal, outcomes, time blocks and the plan's status. "Plan my day"
  opens an agent in the app's terminal that reads the brief, your goals and
  your calendar and proposes a plan; every correction is saved as a new
  version with the new `kb-dayplan` command. Your Google Calendar (through
  Claude Code) is written only when you ask, only with Vepol's own marked
  events, and not at all if a busy event overlaps an agreed block. The
  evening retro compares the day with the confirmed plan.
- **A morning brief you read in a minute.** The brief is short and
  phone-first: the focus, the day plan and the main actions, with decisions,
  mail and ideas only when there are any. Point `KB_HEALTH_METRICS` at a
  folder of daily `health-morning/v1` files and it opens with last night's
  sleep and recovery; without it the brief never mentions health
  ([Health in the brief](../health-in-the-brief.md)).
- **Your language.** Briefs, retros, the audio digests, the arXiv and research
  digests and their fixed labels follow `language:` in
  `~/knowledge/personal/profile.yaml`, with English as the default. The
  repository itself is now English-first.
- **A fresh install runs its daily routine.** The planner no longer crashes on
  the empty location line install writes, so the routines start on day one.
  Without Telegram, the brief, the retro and the digests save their output and
  let the next routine run; once you set Telegram up, a rerun sends the saved
  brief without a new model call. The evening retro now reads the Telegram key
  install writes, the local Qwen voice works, and Money Radar runs on schedule
  once you switch it on.
- **A nightly knowledge refresh.** At 06:30 `kb-consolidate` reads what each
  project logged since the last pass and applies point edits to its
  `state.md`, keeping only edits that match the page and cite a log or daily
  note. Every run leaves a report and a backup of the page under
  `~/knowledge/.orchestrator/consolidate/`. It stays idle until you set it up
  (below).
- **Vepol Desktop keeps track of the work.** A session started from a task
  shows that task and moves to Done when the task closes. You can run several
  sessions of one agent in one project, and every terminal agent gets a real
  title. Backlog, Ready and Blocked tasks have a Close button with an Undo
  (`kb-board cancel` and `reopen`), and the Automations view shows why a
  routine failed: quota, model, auth, network or timeout.
- **Vepol's hooks for the Claude Code settings you already have.**
  `~/knowledge/bin/kb-claude-hooks --check` names the missing session hooks,
  and `--apply` adds only those, after a timestamped backup. Without them,
  Claude Code starts without your knowledge base and sessions are not
  captured.
- **Safer defaults.** A new install's `~/.claude/settings.json` allows only
  reading `~/knowledge` and running `~/knowledge/bin` commands. The brief's
  and the retro's Claude fallback cannot edit files or run commands. Your
  Telegram token no longer reaches the agent that writes the brief, and the
  retro and `kb-channel-send` no longer put it on a `curl` command line.
  `kb-codex-cleanup` stops only Vepol's own processes.
- **A guide to the daily routine.** [docs/daily-routine.md](../daily-routine.md)
  covers every scheduled step, how to switch it off and what to check when
  something does not arrive. Contributors get
  [CONTRIBUTING.md](../../CONTRIBUTING.md) and a CI run on macOS for every
  pull request.

## What stays off until you act

- **The nightly refresh** runs and changes nothing until
  `~/knowledge/hierarchy.yaml` exists. Create it once with
  `kb-rebuild-registry bootstrap`, then `kb-rebuild-registry apply`.
  `kb-child-rollup` (07:00) has nothing to do until that file names parent
  projects. Creating the file also lets the experimental multi-project cycle
  (07:30 and 20:45) run, for the projects you mark `cycle_enabled: true`.
- **Telegram, mail, calendar and health** need your own bot, Codex with its
  Gmail plugin, Claude Code's Google Calendar connector and a daily health
  file. Vepol works without any of them; the brief leaves health out until
  `KB_HEALTH_METRICS` is set, and mail out until a mail read has succeeded
  once.
- **Experimental, as before:** the multi-project cycle, the auto-executor
  (`kb-execute-next`), the evolution loop and the multi-bot Telegram runtime.

## If you already use Vepol

**Your `processes.yaml` does not get the two new routines.** Install writes
`~/knowledge/personal/processes.yaml` only when it is missing, and upgrades
never rewrite it, so your schedule stays yours. To get the nightly refresh,
add these two blocks to that file, for example above the `mail-morning`
block:

```yaml
- id: consolidate
  enabled: true
  when: "06:30"
  run: kb-consolidate
  outputs: [file]

- id: child-rollup
  enabled: true
  when: "07:00"
  run: kb-child-rollup
  outputs: [file]
```

What the upgrade does and does not change in your own files:

- **The Vepol line in `~/.claude/CLAUDE.md` is fixed for you.** A 1.1.1
  install wrote `<!-- @include ~/.claude/.vepol/CLAUDE.managed.md -->`, which
  Claude Code ignores. The upgrade replaces that one line inside Vepol's block
  with `@~/.claude/.vepol/CLAUDE.managed.md`, saves a copy of the file as
  `~/.claude/CLAUDE.md.bak-<date>-<time>` and prints what it changed. Nothing
  else in the file changes.
- **The hub contract stays as you have it.** `~/knowledge/AGENTS.md` and
  `~/knowledge/CLAUDE.md` belong to you, so the upgrade never overwrites them,
  and an existing install keeps the 1.1.1 contract. The upgrade prints
  "differs from this version's — not overwritten" for each one that differs.
  To see what changed (use your clone's path if it is not `~/vepol`):

  ```sh
  sed "s|__HOME__|$HOME|g" ~/vepol/knowledge/AGENTS.md | diff ~/knowledge/AGENTS.md -
  diff ~/knowledge/CLAUDE.md ~/vepol/knowledge/CLAUDE.md
  ```

  To take the new contract, keep copies first, then write the files the way
  install writes them for a new hub:

  ```sh
  cp -p ~/knowledge/AGENTS.md ~/knowledge/AGENTS.md.bak-$(date +%Y%m%d-%H%M%S)
  cp -p ~/knowledge/CLAUDE.md ~/knowledge/CLAUDE.md.bak-$(date +%Y%m%d-%H%M%S)
  sed "s|__HOME__|$HOME|g" ~/vepol/knowledge/AGENTS.md > ~/knowledge/AGENTS.md
  cp ~/vepol/knowledge/CLAUDE.md ~/knowledge/CLAUDE.md
  ```

  Then copy any rules of your own back from the copies, and run
  `cd ~/vepol && ./install.sh --apply` once. Until that run records the new
  files, `kb-doctor install-health` reports both as locally modified
  (`install-hash-drift`, P1).
- **Change two lines in `~/.claude/settings.json` by hand.** If install
  created that file, `permissions.allow` holds `"Bash(~/knowledge/bin/*:*)"`
  and `"Bash(/Users/<you>/knowledge/bin/*:*)"`. Current Claude Code warns
  about this form and matches no command with it. Change them to
  `"Bash(~/knowledge/bin/*)"` and `"Bash(/Users/<you>/knowledge/bin/*)"`.
  Install and upgrades never rewrite this file.
- **LaunchAgent files are kept byte for byte.** No install or upgrade rewrites
  a `com.knowledge.*.plist` that already exists, so yours keep the 1.1.1
  `PATH`, without the `~/.local/bin` that new ones get at the end. Vepol's
  routines look in `~/.local/bin` for Claude Code, Codex and NotebookLM
  themselves, so they find them there either way.
- **Session capture on a Python newer than 3.14.** If your sessions were never
  captured, check with
  `uv run --directory ~/claude-memory-compiler python -c "import claude_agent_sdk"`.
  If that fails, run `cd ~/vepol && VEPOL_ENABLE_MEMORY_COMPILER=1 ./install.sh --apply`
  once: an upgrade without that variable keeps session capture as it is,
  while this run pins Python 3.12 for it and syncs again.

Changes that can break a habit or a script:

- **Prerequisites.** Python 3.10 or later and bash 5 or later are required;
  macOS ships bash 3.2. Node and Bun are no longer required.
- **The brief's time.** `kb-planner` records a fixed brief time, `KB_BRIEF_HM`
  (07:00 by default), instead of one tied to sunrise. The brief still runs
  when `processes.yaml` says: by default after the 07:15 mail read.
- **A manual brief before 06:00 is a preview.** It is written to
  `briefs/<date>-preview-HHMM.md`, so the scheduled brief still goes out
  (`KB_BRIEF_PREVIEW_BEFORE` moves the cut-off).
- **`kb-brief` when no agent answers** still exits 1 and saves no brief. Its
  message now names the reason for each agent it tried and no longer shows
  `rc=75`.
- **`delivery:` in the brief's day file** says `not_configured` when Telegram
  is not set up; it said `telegram_failed`.
- **`kb-channel-send` exit codes.** 3 now means Telegram is not configured (it
  was 2) and 4 a failed send (it was 3). `kb-channel-send-audio` exits 3
  instead of 20 when Telegram is not configured. Long messages are split into
  as many parts as they need.
- **`kb-task` output** is one line, `✓ Added to … board (id: <id>)`; use
  `--json` for kb-board's JSON result.
- **`kb-orchestrator-run`** no longer passes `--model claude-opus-4-7`; set
  `CLAUDE_MODEL` to choose a model. Its Claude lane is read-only unless the
  caller passes the new `--allow-edits`.
- **The interactive install** asks about the local Qwen voice after the
  Telegram question, so scripts that pipe answers by position need updating.
  `install.sh --apply --audio-backend local_qwen` exits 11 when only the voice
  failed.
- **`kb-doctor install-health --strict`** exits 1 until the Python packages
  from `requirements.txt` are installed (a new P1, `python-packages-missing`).
  `kb-doctor agent-entrypoint --strict` exits 1 on any P1. A `~/.codex`
  folder without the Codex CLI, as the ChatGPT and Codex desktop apps leave
  it, is now the info line `codex-optional-absent`, not the P1
  `codex-missing`.
- **New refusals with their own exit codes.** `kb-rebuild-registry bootstrap`
  exits 2 instead of overwriting an existing migration table.
  `kb-spawn-project` exits 3 when there is no `registry.md`.
  `kb-orchestrator-cycle` exits 75 at the start when an autonomy-gate variable
  is set and no safety scanner is installed.
- **Time zone.** Mail windows, calendar reads and writes, follow-up reminders
  and the day plan use `KB_TZ`, then `TZ`, then your Mac's zone, instead of an assumed
  Europe/Madrid.
- **A Russian profile.** Briefs, retros and digests stay in Russian. New
  project templates, a few labels and most terminal messages are now English.
- **Your existing files stay.** An existing `~/.claude/settings.json` is not
  replaced and gets the hooks only through `kb-claude-hooks --apply` (or
  `VEPOL_MERGE_HOOKS=1`).

## Upgrading

Check the two new prerequisites first:

```sh
python3 --version   # 3.10 or later
bash --version      # 5 or later; brew install bash
```

Then update as usual:

```sh
cd ~/vepol && ./upgrade.sh
```

`upgrade.sh` moves the clone to the v1.2.0 tag before it re-runs the
installer. If a prerequisite is missing, the installer stops with "Required
tools missing" and the commands to install them, and the clone stays on
v1.2.0 with the install unfinished. Install what it names, then run
`./upgrade.sh` again: on the current tag it re-applies the installer.

Scheduled tasks and session capture that are already installed are kept. If
`kb-doctor install-health` reports `python-packages-missing`, run the `pip`
command it prints. If you use Vepol Desktop, quit and reopen it; run
`face/desktop/build.sh` again only if you want the About box to say 1.2.0.
