# v0.7.2 — Idea-to-task promotion works end to end

`kb-idea promote --create-task` now does what the docs promise: it turns a
triaged idea into a real `Ready` task on your kb-board, linked back to the
idea card.

## What you get

```bash
kb-idea capture "Ship the onboarding checklist"
kb-idea triage idea-... --priority P1 --materiality cheap-test \
  --next-action "Draft checklist" --evidence "Checklist page exists"
kb-idea promote idea-... --project hub --create-task
```

The promotion creates a `Ready` task in the target board (`--project hub`
for the hub board, any other slug through `projects/<slug>/backlog.md`),
carrying:

- the idea's title as the task title,
- the idea's triaged priority (override with `--priority`),
- the idea's expected evidence as the task's acceptance criterion,
- an `idea_id` field linking the task back to the card,
- optional `--context` text as the task body.

The card is stamped `promoted` with the task's `plan_item_id` mirrored back.
Promotion is idempotent — re-running it finds the existing task instead of
minting a twin. The board file is written atomically under the same lock and
format check `kb-board append` uses, and the board mutation never nests
inside the idea-card lock.

## What was broken

The `--create-task` flag shipped in the CLI, the docs, and the acceptance
test — but the library function behind it never learned the keyword, so every
`kb-idea promote` invocation (with or without the flag) crashed with
`TypeError`. This had been true in every release since v0.6.0, and it is why
`tests/run-all.sh` failed on the Idea Intake vertical. The acceptance test
that shipped in v0.6.0 now passes as written; no test was modified.

## Upgrading

Pull the release. No configuration, data, or board-format changes.
