# v1.1.0 — See where every project stands

Vepol 1.0 put your agents and their work in one window. 1.1 makes that window
open on what Vepol remembers. The first screen shows every project's knowledge
at a glance, and one click on a project shows where it stands: its current
state, the sessions working on it and its task board, on one page.

Sessions got easier too. A new session can start in any project, or in a folder
that is not a project yet. The terminal runs every agent CLI Vepol knows, not
only Claude Code and Codex. Open sessions stay as tabs, and the tabs come back
after a restart.

This release changes Vepol Desktop only. The stable core (the knowledge folder
layout, the `kb-board` task board, install and upgrade), the other `kb-*`
commands and `processes.yaml` are unchanged.

## What you get

- **Memory, first.** The app opens on one card per knowledge base: what is
  happening now, what is next, the last decision and the last activity, with a
  status that says whether the project's state is up to date.
- **One screen per project.** Its state, its sessions with their states and its
  task board, together.
- **Start anywhere.** Pick any project for a new session, or turn any folder into
  a project from the same dialog.
- **Six agents in the terminal.** Claude Code, Codex, agy (Antigravity), Hermes,
  OpenCode and Grok, each shown as its icon.
- **Tabs that survive a restart.**

## Memory

Your knowledge base is what makes agents useful from one session to the next.
Until now the app showed it only as a file tree, and only beside an open
session. Now the app opens on Memory.

Each card is one knowledge base: your hub first, then every project, the most
recently active first. A card shows what is happening now (from `state.md`),
what is next (the first task in progress, else the first ready one, read
through `kb-board`), the last decision in `decisions/` and the last entry in
`log.md`. Its status says «Up to date», «Needs review» (the log is more than
three days newer than the state) or «No state file».

Everything is read at the moment you look, from files your projects already
have. The app never writes to your knowledge, and nothing new is required in
the folder layout.

## The project screen

Click a project in the sidebar, or its card in Memory, and one screen shows:

- **State.** A highlighted box with the snapshot from `state.md`, the next task
  and when the state last changed. «Show full state» unfolds the whole file.
- **Sessions.** Every session of the project with its state in colour. The ones
  waiting for you or with a running agent come first. A click opens the session
  in a tab.
- **Board.** The project's tasks in columns: In Progress, Review, Blocked (only
  when something is blocked), Ready and Backlog, with Done folded. The board is
  read-only; `kb-board` and your agents still own the tasks.
- **Decisions, History, Lessons and Files**, rendered as Markdown.

The screen refreshes every 30 seconds while you look at it, and never closes
anything you opened. «New session here» asks which agent to start in that
project.

## Sessions

**Any project, or a new one.** «+ New session» (and «+» on a board column) asks
for the project: the hub and every project linked into it, the most recently
active first, with search. «Add project…» opens the macOS folder panel, where
you can also create a folder. The folder becomes a Vepol project through your
hub's own `new-wiki`, which adds the project files where they are missing and
never overwrites a file. The session then starts there.

**Every agent you have installed.** The in-app terminal now starts agy, Hermes,
OpenCode and Grok as well as Claude Code and Codex. The dialog lists the agents
installed according to your hub roster and shows each one's availability, as
information only: the terminal opens either way, and the agent itself reports a
login or quota problem. Each agent is shown as its icon wherever the app names
it.

**Tabs.** Every session you open is a tab, and closing a tab stops nothing. Quit
and reopen the app, and the same tabs come back with the same one selected.

**A terminal that behaves like one.** The terminal runs your login shell and
types the agent command into it. Leave the agent, and you are back at a working
prompt. When the agent exits, the terminal says so, and Start opens a new one
for the session on screen. Nothing restarts on its own.

**Titles you recognise.** A Claude session takes its title from Claude itself:
your `/rename`, else Claude's own title, else your first prompt.

The sidebar now lists projects only, with a green dot where an agent is
running; the app's sections sit above them.

## Try it on sample data

`demo/workspace/` is an invented company with a hub and three projects. After
building the app, `face/demo.sh` copies it to `~/.vepol/demo-workspace/` and
opens it on port 8782 with its own state and its own tmux server. Your own
sessions and your `~/knowledge` are not touched.

## Fixed

- macOS 26 no longer shows the app icon as a small V inside a grey tile: the
  icon is drawn on the exact macOS icon shape.
- Claude starts from its native install before a Homebrew copy, so
  `claude update` takes effect in the app.
- The session header follows the agent's start and exit within a second.

## Upgrading

Update Vepol as usual:

```sh
cd ~/vepol && ./upgrade.sh
```

Then rebuild the app, since its native shell and icon changed, and reopen it:

```sh
cd ~/vepol/face
./desktop/build.sh
open desktop/build/VepolDesktop.app
```

The Python requirements are unchanged. Your sessions, their history and their
board stages carry over. No data migration is needed.

## Known limits

- Everything in 1.0's known limits still holds: macOS 13 or later, Apple
  Silicon, built from source, signed for local use only and not notarized.
- agy and Grok ask once per folder whether to trust it, in the terminal.
- Hermes works in the folder set by `terminal.cwd` in `~/.hermes/config.yaml`,
  not in the project folder.
- Memory, the project screen, Tasks and Automations are read-only.
- Claude Code is the agent used day to day in the in-app terminal. agy, Hermes,
  OpenCode and Grok were each started live in a project folder. Codex in the
  terminal is covered by the automated tests with a stand-in agent.
