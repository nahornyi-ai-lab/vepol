# v0.8.1 — Board writers can no longer erase your backlog

A `kb-board` mutation could replace your whole `backlog.md` with a single task,
silently, exiting 0. This release makes every writer refuse rather than publish
over a board it cannot faithfully reproduce.

## What was broken

Every mutating writer followed the same shape: read the board, parse it,
re-render what parsed, atomically replace the file. The parser keeps only
recognized `## <status>` sections and task blocks — so prose, hand-written
notes, and legacy headings (`## Open`, `## In progress`, `## Notes`) were
dropped, and the rewrite was published anyway. The *candidate* board was
validated before writing; the *original* never was.

On a board whose tasks all sat under unrecognized headings, nothing parsed at
all, and one `kb-board append` replaced the entire file with the single task
just added. `knowledge/` is deliberately not under git, so there was nothing to
restore from.

This affected `kb-board append`, every `mutate_file` operation (claim, ready,
heartbeat, progress, request-review, close), `sweep`, and
`kb-idea promote --create-task`.

## What changed

A non-empty board that fails `kb-board check` is now refused before any write:

```
$ kb-board append backlog.md "New task" --plan-item-id example --status Ready
kb-board: EORIGINAL: existing board at backlog.md is not in canonical kb-board
multiline format (EFMT); mutating would silently drop unrecognized content.
Inspect with `kb-board check`; canonicalize drifted boards with
`kb-board fmt <path>` (review dry-run output, then --write); migrate legacy
one-line boards with `kb-board migrate <path>` (review dry-run output, then
--write).
```

The file is left byte-identical. The message names the offending check codes
and the remedy commands.

Deliberate exemptions, so nothing that used to work stops working:

- **Empty and title-only boards stay mutable** — bootstrap (`kb-board append`
  to a fresh board, the `new-wiki` template) is unaffected.
- **A sweep with nothing to move stays a silent no-op** on any board, so
  schedulers ticking over legacy boards do not start failing.
- **`kb-board check`, `hash`, and `list` are read-only and ungated.**
- **`kb-board fmt --write` and `kb-board migrate --write` are not gated** —
  they are the remedy commands, and both print a dry run by default.

`kb-board` also reports structured mutation failures instead of a Python
traceback: `{"ok": false, "code", "message"}` with `--json`, or
`kb-board: <code>: <message>` on stderr, exit 1. This covers every mutation
error code, not just the new one.

## Behavior change

Mutations on a non-canonical board now **refuse** instead of quietly
canonicalizing it. If you hit `EORIGINAL`:

1. `kb-board check <path>` — see exactly what is wrong.
2. `kb-board fmt <path>` — dry run; review what canonicalization would keep.
3. `kb-board fmt <path> --write` when you are satisfied. For a legacy one-line
   board, use `kb-board migrate <path>` the same way.

Note that `fmt --write` is lossy for prose and unrecognized content — that is
why it defaults to a dry run, and why the refusal points you at it rather than
doing it for you. Prose belongs in `state.md`, `log.md`, or a thematic page;
`backlog.md` is the task board.

## Upgrading

Pull the release. No configuration or data migration. Boards that already pass
`kb-board check` are unaffected — no behavior change at all on the mutation
path.
