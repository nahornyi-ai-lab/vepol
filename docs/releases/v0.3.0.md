# Vepol v0.3.0 — Idea Intake

Vepol v0.3.0 adds **Idea Intake**, an event-driven process for ideas you write
or dictate.

The goal is simple: an idea should not disappear in chat history, voice notes,
or memory. Vepol captures it into a structured markdown card, lets agents
triage and critique it, ranks it against your priorities, and only then offers
concrete next steps through the daily brief, task board, and calendar approval
flow.

## What Ships

- `kb-idea capture` creates an atomic canonical card under
  `personal/ideas/<idea-id>.md`.
- `personal/ideas.md` renders the dashboard from those cards.
- `kb-idea triage` records priority, materiality, strategic lines, next action,
  and expected evidence.
- `kb-idea brief` exposes ready and promoted ideas to the daily planning flow.
- `kb-idea promote --create-task` creates a normal markdown `kb-board` task and
  writes the task pointer back to the idea card.
- `kb-idea calendar propose` prepares a calendar block without writing to the
  calendar.
- `kb-idea calendar approve` records the approved external event ID.
- `kb-idea done` closes the loop with an outcome.

## Source Of Truth

Before promotion, the idea card owns the idea state. After promotion,
`kb-board` owns execution state. The card keeps the pointer and outcome mirror,
but does not duplicate task status.

This keeps Vepol from creating split-brain work state across separate files.

## Process Shape

Idea Intake is **not** a scheduled `processes.yaml` job. It starts when an idea
arrives:

```text
text or voice event
  -> capture card
  -> dashboard render
  -> triage / priority
  -> critique
  -> daily brief proposal
  -> kb-board task
  -> calendar approval
  -> outcome
```

Background processes can consume the resulting cards later, but they do not
initialize the process.
