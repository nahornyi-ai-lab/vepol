# v0.6.0 — Selectable NotebookLM or local Qwen audio

Vepol keeps the existing NotebookLM audio route and adds local Qwen3-TTS 1.7B
as a second option. Text generation is unchanged. After the final digest is
ready, one setting chooses its destination:

- `notebooklm` — Audio Overview stays in NotebookLM, without Telegram or MP3
  download;
- `local_qwen` — the existing on-demand renderer creates an MP3 and sends it
  through Telegram.

## Why this changed

Some installations prefer NotebookLM's managed Audio Overview; others want the
exact local MP3 in Telegram. Vepol now supports both without changing capture,
prompts, synthesis, Retro, freshness, or report generation. There is no silent
fallback: an error in the selected adapter does not invoke the other one.

## Runtime model

- Select with `kb-digest-migrate --audio-backend notebooklm|local_qwen`.
- For local Qwen, install once with `kb-tts-install`.
- No server or daemon is started.
- Each digest launches the renderer, writes an MP3, sends it through Telegram,
  and releases the model process.
- Fresh installs default to the backward-compatible NotebookLM route; upgrades
  preserve their current managed route unless selection is explicit.
- Model weights, credentials, caches, and local runtime markers are not part of
  the repository.

Configure Telegram in `~/knowledge/personal/.secrets`:

```bash
TELEGRAM_BOT_TOKEN=...
TELEGRAM_CHAT_ID=...
```

Then install and select the local route:

```bash
kb-tts-install
kb-digest-migrate --file ~/knowledge/personal/processes.yaml --audio-backend local_qwen
```

To keep audio in NotebookLM instead:

```bash
notebooklm login
kb-digest-migrate --file ~/knowledge/personal/processes.yaml --audio-backend notebooklm
```

## Freshness and duplicate-send safety

Morning delivery now records `morning-input/v1`, a semantic snapshot of the
captured research, Money Radar, brief, mail, idea, project, board, log, and
escalation inputs. A same-day manual run cannot silently occupy the later
scheduled slot when those inputs change. Unchanged content does not resend,
even if file mtimes or untrusted-source nonces change.

The per-day lock serializes concurrent callers. A Telegram timeout after upload
remains deliberately ambiguous and requires human reconciliation; Vepol does
not automatically retry a send that may already have arrived.

## Upgrade and rollback

Upgrade normally; without an explicit backend option the installer preserves
the existing route. The schedule migration changes only exact managed digest
outputs and leaves custom blocks untouched.

Rollback can select NotebookLM before restoring v0.5.0. Downloaded Qwen files
may remain inert on disk; no model process remains resident without a render.

## Verification

The release suite covers local rendering lifecycle, Telegram multipart
transport, privacy boundaries, morning/evening isolation, stage retries and
caps, semantic freshness, concurrency, ambiguity, migration, installation, and
source-only distribution.
