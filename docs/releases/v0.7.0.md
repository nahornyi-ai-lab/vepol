# v0.7.0 — People Notebook

Vepol adds a review-gated relationship memory and moves the local voice to a
cleaner model. Capture, prompts, Retro, and report generation keep their
existing behavior.

Two things are new:

- **People Notebook** — an address book that proposes contact cards from the
  material Vepol already sees, and never writes a new person without your
  approval.
- **BF16 local voice** — the on-demand Qwen renderer moves to the BF16 model
  snapshot for cleaner speech.

## People Notebook

Vepol now keeps a lightweight relationship memory. It proposes contact cards
from four sources it already has access to:

- your project logs,
- the mail people-envelope,
- your private Telegram dialogs (read-only, on your own account),
- calendar attendees.

Every genuinely new person waits in a **Telegram review queue**. You keep or
skip each one with a single tap — nothing about a new person is written to the
notebook without your approval. A contact you already have gets only a
content-free sighting (that you crossed paths again), never new prose behind
your back. Optional enrichment runs through your configured Codex CLI.

Design boundaries:

- **Staged-only.** New people are proposed, not auto-saved. The review queue is
  the gate.
- **Read-only Telegram.** The collector reads dialog identity through your own
  account and never sends, edits, or joins anything. It carries no message text
  into the notebook by schema.
- **No credentials in the repository.** Telegram API keys and session state live
  in your local secrets, not in Vepol.
- Company and asset roll-up from these sightings is scoped and stays disabled
  until you turn the orchestration cycle back on.

## Cleaner local voice (BF16)

The on-demand local runtime moves its pin from the 8-bit build to the BF16
Qwen3-TTS VoiceDesign snapshot. The installer around it is hardened: a
non-blocking install lock, verified immutable release directories, atomic
`install.json` promotion, and byte-exact preservation of any prior install
marker so a rollback never loses the previous weights. The model still ships no
weights or credentials in the repository, loads only for a single render, and
exits afterward — no daemon.

## Daily pipeline hardening

The scheduled daily loop is more reliable and less noisy:

- The learning digest reads full arXiv papers by default (`kb-learning-arxiv`
  fetches and caches the PDF, extracts text, and analyzes the paper text rather
  than only the abstract).
- Grok/X/Reddit social checks are opt-in: the learning digest no longer calls
  Grok by default or renders empty social boilerplate. Set `social_check: grok`
  in `personal/daily-research.yaml` to re-enable it.
- Daily and retro audio route through the on-demand local Qwen runtime and
  Telegram when local audio is selected; missing runtimes stay report/speech-only.

## Upgrade and rollback

Upgrade normally. The People Notebook is review-gated, so nothing is written
until you act on the queue. The audio changes preserve your selected route
(NotebookLM or local Qwen); no capture, prompt, or Retro behavior changes.

To use local Qwen audio, run `kb-tts-install` once; the BF16 snapshot installs
into its own immutable release directory and the previous marker is preserved.
Rollback can select the NotebookLM route before restoring v0.6.0; downloaded
model files may remain inert on disk and no model process stays resident without
a render.

## Verification

The release suite covers staged contact extraction and dedup across all four
sources, the read-only Telegram collector's complete-window coverage and
crash/retry safety, review-queue keep/skip, the BF16 installer's immutable
release and atomic promotion, privacy boundaries, and source-only distribution.
