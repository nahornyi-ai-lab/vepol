# v1.1.1 — A clean first five minutes, and failures that say why

Vepol 1.1.1 fixes the first five minutes after install and makes failures say
what actually went wrong. The stable core keeps its contracts; the one change
in how it behaves is that `upgrade.sh` now follows release tags.

## What you get

- **A green health check on a fresh install.** `kb-doctor` no longer reports a
  P0 on a hub that simply has no projects yet. It prints one info line instead:
  «no projects registered yet — create one with new-wiki». A registry whose rows
  exist but cannot be read still reports the P0.
- **A demo brief built from the demo.** `kb-demo brief` now finds its helpers
  next to itself, so the demo prompt carries the demo projects instead of empty
  fallbacks. The demo stays synthetic: no calendar read, and the brief is only
  printed, never delivered.
- **Python that works on any Mac.** `kb-orchestrator-cycle` and the
  `kb-multibot-*` scripts start with `#!/usr/bin/env python3`. Apple's
  `/usr/bin/python3` refuses to run until the Xcode licence is accepted.
- **`new-wiki` in English, with a clear error.** A folder that does not exist
  gives `new-wiki: folder not found: <path>` and exit 1, and nothing is created.
  It no longer writes a project `CLAUDE.md`: Claude Code reads `AGENTS.md`
  directly, and a `CLAUDE.md` above a project switches that off.
- **Failure reasons are the real cause.** When a provider fails, Vepol keeps
  the line that explains it (quota, unsupported model, auth, network, timeout)
  rather than the first or last line of output. A Codex usage limit counts as
  a rate limit, with the real «try again at …» time. An empty Codex answer
  counts as a failure. The morning brief says why mail is unavailable and for
  how many days in a row.

## Upgrades now follow releases

`upgrade.sh` moves to the newest release tag (`vX.Y.Z`; pre-release tags are
skipped) instead of the tip of `main`. `./upgrade.sh --check` compares your
release with the newest tag. A clone with local edits still stops and asks you
to resolve them by hand.

If you are on 1.1.0, run `./upgrade.sh` once as usual. From 1.1.1 on, you only
ever land on a tagged release.

## Not in this release

The bounded, quota-aware retries in the scheduler and the local voice fallback
for the morning digest. Both were running on the maintainers' machine at
release time and were not yet part of this repository.
